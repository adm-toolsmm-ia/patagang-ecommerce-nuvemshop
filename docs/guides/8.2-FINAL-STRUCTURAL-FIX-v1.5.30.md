## 🎯 O Problema Raiz (Confirmado)

Após **investigação profunda**, identificamos que o cinza cascata é causado por:

### 1️⃣ **Estrutura HTML Plana (MAL DESENVOLVIDA)**
```html
<!-- ANTES: Tudo plano no body, sem isolamento -->
<body>
  {% snipplet "header/header-advertising.tpl" %}
  {% snipplet "header/header-patagang.tpl" %}
  {% template_content %}
</body>
```

**Problema:** Sem containers intermediários, se body ou qualquer ancestral tiver background, TUDO herda.

### 2️⃣ **CSS Incompleto em header-patagang.tpl (LINHA 206)**
```css
@media(max-width:768px){
    body:not(.has-ad-bar) .pg-header {
        min-height:56px!important;
        padding-top:6px!important;
    }
    /* ❌ FALTA: Nenhuma regra para body.has-ad-bar .pg-header */
}
```

**Problema:** Quando `.has-ad-bar` está PRESENTE, o header em mobile **não tem styling definido** → herda background de pai.

### 3️⃣ **Variável Dinâmica `$main-foreground` Cascatando**
```scss
$main-foreground: {{ settings.text_color }}  /* Cinza da loja */

.section-advertising { background-color: $main-foreground; } /* Comentado, mas... */
.placeholder-container { background: rgba($main-foreground, 0.1); } /* Ativo! */
.placeholder-fade { background: rgba($main-foreground, 0.2); } /* Ativo! */
/* ~45+ classes com rgba($main-foreground) como background */
```

**Problema:** Muitas classes usam essa cor como background — se elemento pai tiver uma delas, cascata cinza.

## ✅ SOLUÇÃO APLICADA (v1.5.30)

### 🏗️ Refatoração HTML — Seções Semânticas Isoladas

```html
<!-- DEPOIS: Cada seção em seu próprio <section> com role semântico -->
<body>
  <!-- SEÇÃO 1: TOP BANNER (isolado) -->
  <section class="patagang-section-top" role="banner">
    {% snipplet "header/header-advertising.tpl" %}
  </section>

  <!-- SEÇÃO 2: HEADER NAVIGATION (isolado) -->
  <section class="patagang-section-header" role="navigation">
    {% snipplet "header/header-patagang.tpl" %}
  </section>

  <!-- SEÇÃO 3: MAIN CONTENT (isolado) -->
  <main class="patagang-section-content" role="main">
    {% template_content %}
  </main>
</body>
```

**Benefício:** Cada seção é **estruturalmente independente** — nenhuma cascata possível entre elas.

### 🎨 CSS Explícito — Backgrounds Definidos

```css
/* L1: Top section — transparent */
section.patagang-section-top {
    background-color: transparent !important;
    background-image: none !important;
}

/* L2: Header section — transparent */
section.patagang-section-header {
    background-color: transparent !important;
    background-image: none !important;
}

/* L3: Content section — WHITE (explicit) */
main.patagang-section-content {
    background-color: #ffffff;
}
```

**Benefício:** Backgrounds **explicitamente definidos** em cada nível — nenhuma herança surpresa.

### 📱 Mobile Breakpoints — Explicit Spacing

```css
@media (max-width: 768px) {
    section.patagang-section-top {
        border-bottom: 1px solid rgba(0,0,0,0.05);
    }

    section.patagang-section-header {
        border-bottom: 1px solid rgba(0,0,0,0.08);
    }
    section.patagang-section-header .pg-header {
        min-height: 56px !important;
        padding-top: 8px !important;
    }

    main.patagang-section-content {
        margin-top: 0;
    }
}
```

**Benefício:** Cada seção tem seu **próprio styling em mobile** — não depende de outras.

## 🎓 Lições para Refatoração Futura

Este projeto confirma que:

1. **Estrutura HTML plana é perigosa** — sempre use containers semânticos
2. **CSS incompleto causa herança inesperada** — complete todas as variações (`.has-X` + `.not(.has-X)`)
3. **Variáveis dinâmicas de tema precisam de reset explícito** — não confie em comentários
4. **Mobile breakpoints precisam de ambas as regras** — a versão oposta pode estar ausente
