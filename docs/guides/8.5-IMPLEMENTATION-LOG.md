## 🚀 **PRIORITY 1: Lazy-Load Olark (In Progress)**

### Status: 🔄 IMPLEMENTATION PHASE

**Goal:** Move Olark chat script from initial load to lazy-load (after DOMContentLoaded)

**File:** `theme-deploy-corrigido/static/js/external.js.tpl`

**Location:** Lines 5-12 (within {% if store.live_chat %})

**Current Implementation:**
```tpl
{% if store.live_chat %}
	{# Olark code for store chat #}
	<script>
		[... full Olark script inline in template ...]
		olark.identify('{{store.live_chat | escape('js')}}');
	</script>
{% endif %}
```

**Problem:**
- Olark script is loaded in external.js.tpl (blocking render)
- Entire script (~20K) is evaluated before page displays
- Not critical for initial page load
- User experience delayed by ~200-300ms waiting for chat widget

**Solution:**
- Extract Olark script to separate lazy-load block
- Load script AFTER DOMContentLoaded event fires
- Keep conditional: only load if store.live_chat is configured
- Benefit: Page renders immediately, chat loads in background

**Implementation Plan:**
```
STEP 1: Extract Olark script text (document for reference)
STEP 2: Move to conditional lazy-load pattern in JS
STEP 3: Verify script still initializes with store.live_chat ID
STEP 4: Test: Chat widget appears correctly after page load
STEP 5: Measure: Confirm savings ~21K
```

**Risk Assessment:**
- ✅ LOW — Chat is non-critical, lazy-load won't break functionality
- ✅ Already has conditional guard ({% if store.live_chat %})
- ⚠️ Must verify: Script dependency order (check if Olark var accessed before load)

**Timeline:** ~2 hours
