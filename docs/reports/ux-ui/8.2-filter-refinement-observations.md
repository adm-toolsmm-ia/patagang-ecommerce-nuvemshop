## 🎨 PONTO DE ATENÇÃO #1: Design dos Componentes de Filtro

### Observação
O design dos componentes de filtro (botão "Filtrar", dropdown "Ordenar", chips de filtros) está esteticamente abaixo do padrão esperado e destoante do design system da loja.

### Detalhes
- **Botão "Filtrar":** Aparência genérica, sem refinamento visual
- **Dropdown "Ordenar":** Ícone e layout precisam alinhamento com design system
- **Chips de Filtros:** Visual não segue padrão de cores/tipografia esperado
- **Espaçamento/Gap:** Controles poderiam ter melhor distribuição visual

### Impacto
- ⚠️ Experiência do usuário degradada em páginas de categoria/busca
- ⚠️ Inconsistência com design tokens do site (Story 8.1)
- ⚠️ Confiabilidade visual reduzida em conversão (filtros parecem "quebrados")

### Recomendação
Criar **Story de Refinamento UX/UI — Filtros & Controls** com escopo:
- Redesenhar botão "Filtrar" conforme design system
- Refinar dropdown "Ordenar" com ícones consistentes
- Estilizar chips de filtros com cores/tokens corretos
- Validar espaçamento em mobile/tablet/desktop
- A/B testing em produção com novo design

### Arquivo Técnico Relacionado
- `theme-deploy-corrigido/static/css/style-async.scss.tpl` (linhas 7595-8017)
- Seção: "Filters, sort dropdowns, and control styling"

## ⚠️ PONTO DE ATENÇÃO #2: Renderização Dupla / FOUC em Páginas de Categoria

### Observação
Ao acessar páginas de categoria/busca, há um **carregamento duplo visível**:
1. Primeiro: Carrega versão incompleta (algo renderiza)
2. Depois: Muda para versão final/completa

### Sintomas
- Página inicialmente renderiza com layout/conteúdo parcial
- Visual "flashing" entre versão parcial e versão final
- Mesmo sendo "rápido", há dois estados visíveis sequencialmente

### URLs Afetadas
- https://www.patagang.com.br/lancamentos/
- https://www.patagang.com.br/search/?q=Passeio

### Análise Recomendada
Investigar estrutura de renderização em:

**1. Template Structure (layout.tpl)**
- Ordem de carregamento de templates
- Anti-FOUC implementation (verificar se há visibility:hidden aplicado corretamente)
- Async CSS loading (verificar se style-async está causando delay)

**2. JavaScript Execution**
- Verificar se JS está renderizando conteúdo dinamicamente
- Checks para "DOM ready" vs "CSS ready"
- Possível race condition entre HTML + CSS + JS

**3. Nuvemshop Rendering Pipeline**
- Verificar se há renderização server-side vs client-side mismatch
- Liquid template conditionals que causam renderização dupla
- Cache/service worker impactando renderização

**4. Asset Loading Order**
- Critical CSS está sendo aplicado?
- Async CSS timing correto?
- Fonts carregando antes ou depois do conteúdo?

### Impacto
- 🔴 **Performance:** Primeira renderização degradada (não reflete LCP real)
- 🔴 **UX:** Visual instability = User perceives slowness (mesmo que rápido)
- 🟡 **Debugging:** Difícil diagnosticar root cause sem análise profunda

### Próximas Ações
1. **Análise Técnica Profunda**
   - Usar Chrome DevTools "Rendering" tab para capturar paint events
   - Analisar Frame Timeline para identificar momento da renderização dupla
   - Checar Network tab para sequência de asset loading

2. **Criar Story de Investigação**
   - Title: "Investigate Category Page Rendering Behavior — Duplicate Paint Events"
   - Escopo: Deep-dive analysis + root cause identification + fix proposal

3. **Potenciais Fixes**
   - Ajustar anti-FOUC (visibility:hidden em elementos críticos)
   - Consolidar template rendering order
   - Otimizar async CSS loading timing
   - Verificar Liquid template logic para renderizações condicionais

### Arquivo Técnico Relacionado
- `theme-deploy-corrigido/layouts/layout.tpl` (verificar anti-FOUC setup)
- `theme-deploy-corrigido/static/css/style-critical.tpl` (linhas 4343-4354, anti-FOUC styles)
- `theme-deploy-corrigido/static/css/style-async.scss.tpl` (async loading impact)
