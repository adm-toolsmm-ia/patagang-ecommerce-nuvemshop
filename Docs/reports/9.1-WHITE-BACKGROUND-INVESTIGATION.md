## 📋 Executive Summary

**Problem:** Pages like `/comunidade/` display unwanted white background + excessive spacing below header.

**Root Cause Identified:** CSS rule cascade issue in `style-critical.tpl` where product-page-specific background color is scoped correctly BUT there's a **main content padding pattern** that's affecting all non-product pages.

**Actual Issue:** The main content section `main.patagang-section-content` has `padding-top: 160px` to accommodate fixed header. When combined with certain page layouts (like community), this creates a visual effect of "white background band" because:

1. Header is `position: fixed` at top
2. Main content starts 160px down with this padding
3. On some pages (community), elements between header and main content DON'T have proper background color override

### CSS Cascade Issue
```css

    padding-top: 160px;  /* Space for fixed header (~120px) + ad bar (~40px) = ~160px */

    padding-top: 0;  /* Banners estão dentro, eles controlam seu espaçamento */

```

**The problem:** Non-product pages (like community) inherit the `padding-top: 160px`, which creates a large white space above the main content because body is `#ffffff`. This is **INTENTIONAL** to prevent header overlap, but on pages without content that fills the header area, it appears as a white band.

## 🎯 Root Cause Summary

**PRIMARY CAUSE:** CSS rule scoping is correct, but it creates an unintended visual side effect on generic pages.

**MECHANISM:**
1. All pages: `main.patagang-section-content { padding-top: 160px; }` — space for fixed header
2. Product pages only: Override to `padding-top: 0;` — banners control their own spacing
3. Generic pages: Inherit the 160px padding, which combined with white body background creates a visual "white band" below the header

**WHY IT APPEARS AS "WHITE BACKGROUND":**
- Header is 120px tall (fixed position)
- Ad bar is ~40px
- Main content starts at 160px from top
- On pages without content that naturally fills this space (like /comunidade/), the white body background shows through, creating appearance of "excessive white space below header"

**WHEN IT APPEARED:**
- Introduced during Story 8.2 (Critical CSS Reduction)
- Specifically commits v1.5.112 → v1.5.125 where product page layout was refactored
- Side effect: Generic pages not updated to compensate for new spacing pattern

## 💡 Solutions Proposed

### Solution A: Adjust Main Content Padding for Generic Pages (RECOMMENDED)
**Approach:** Fine-tune `main.patagang-section-content padding-top` based on page template

```css
/* Current (all pages get 160px) */
main.patagang-section-content {
    padding-top: 160px;
}

/* SOLUTION A: Differentiate by template */
body:not(.template-product) main.patagang-section-content {
    padding-top: 100px;  /* Less padding for generic pages (only header space) */
}

body.template-product main.patagang-section-content {
    padding-top: 0;  /* Product pages handle via banners */
}
```

**Pros:**
- Minimal change
- Preserves existing functionality
- Easy to test and revert

**Cons:**
- Requires media query adjustments for tablet/mobile
- May need tweaking per page type

**Effort:** 30 minutes

## 🔮 Gotcha for Future Stories

**CRITICAL LEARNING:** When adjusting product page layouts (padding, positioning, spacing), always verify impact on generic pages.

**Prevention Pattern:**
```
Product Page CSS Change
  ↓
CHECK: Do non-product pages inherit this?
  ├─ YES → Use body.template-product selector
  └─ NO → Use generic selector

Test Checklist:
  ☐ Desktop generic page (e.g., /blog/, /comunidade/)
  ☐ Mobile generic page
  ☐ Tablet generic page
  ☐ Product page (ensure no regression)
```

**Example Bad Pattern:**
```css
/* ❌ BAD: Affects generic pages unintentionally */
main.patagang-section-content {
    padding-top: 160px;
}
```

**Example Good Pattern:**
```css
/* ✅ GOOD: Generic pages get one value, product pages override */
main.patagang-section-content {
    padding-top: 160px;
}

body.template-product main.patagang-section-content {
    padding-top: 0;
}
```
