## 📋 User Story

**Como** visitante da Patagang
**Quero** que as páginas home, /lancamentos e /comunidade carreguem sem flash visual (FOUC)
**Para** que minha primeira impressão da loja seja profissional e sem artefatos visuais

---

## 🎯 Acceptance Criteria

- [ ] **AC 1:** Home (`/`): sem flash de layout perceptível no carregamento com cache limpo
- [ ] **AC 2:** /lancamentos: sem flash de layout perceptível no carregamento com cache limpo
- [ ] **AC 3:** /comunidade: sem flash de layout perceptível no carregamento com cache limpo
- [ ] **AC 4:** Nenhuma regressão nas páginas que funcionam corretamente (PDP, checkout, categoria)
- [ ] **AC 5:** CSS crítico (`style-critical.tpl`) permanece < 50 KB após qualquer adição
- [ ] **AC 6:** Score de performance (Lighthouse mobile) não piora mais de 5 pontos

---

## 🔍 Investigação Prévia Necessária (antes de alterar código)

Esta story requer investigação antes de qualquer alteração de código. O @analyst deve mapear as causas antes do @dev implementar.

### Contexto do mecanismo atual:
- `style-critical.tpl` linha 95: `.visible-when-content-ready { visibility: hidden }` (oculta inicial)
- `style-critical.tpl` linha 4427: `.visible-when-content-ready { visibility: visible }` (mostra - vence)
- **Resultado:** Como ambos estão no mesmo arquivo inline, o conteúdo está visível por padrão. Não é a causa do FOUC.
- `style-async.scss.tpl` carrega com `media="print" onload` → carrega após o primeiro render
- `.pg-hero-v2` e seções home só existem em `style-home-v2.css` (carrega bloqueando na home)

### Hipóteses a investigar:

**Hipótese A — /lancamentos e /comunidade são category pages:**
- `category.tpl` usa classes que podem estar APENAS em `style-async.scss.tpl`
- Grid de produtos `.pg-product-grid` ou `.item-product` sem estilo inicial → layout shift ao carregar async

**Hipótese B — Fontes causando FOIT/FOUC:**
- Google Fonts carregadas com `rel="preload"` mas sem `font-display: swap`
- Texto renderiza em fonte fallback → reflow quando fonte carrega

**Hipótese C — Home — hero sem fallback:**
- `.pg-hero-v2` em `style-home-v2.css` (carrega bloqueando)
- Mas se há delay no arquivo, hero aparece sem estilo brevemente

**Hipótese D — `style-async.scss.tpl` carrega regras críticas:**
- Identificar classes above-the-fold em `/lancamentos` e `/comunidade` que estão APENAS no arquivo async
- Mover essas regras específicas para `style-critical.tpl`

## 🔧 Escopo Técnico

### Fase 1: Investigação (sem código) — @analyst + @dev
1. Confirmar tipo de página de `/lancamentos` e `/comunidade` (category.tpl? page.tpl?)
2. Abrir DevTools > Network > Disable Cache em cada página
3. Identificar visualmente QUANDO ocorre o flash (antes/depois de qual recurso carregar)
4. Mapear classes CSS above-the-fold ausentes no carregamento initial
5. Documentar root cause específico

### Fase 2: Implementação (baseada na investigação)
Dependendo da causa raiz encontrada, implementar UMA das soluções:

**Solução A (se classes do grid faltam no critical):**
- Mover classes above-the-fold identificadas de `style-async.scss.tpl` para `style-critical.tpl`
- Max 10-15 regras por batch (CSS Safety Pattern)

**Solução B (se fontes):**
- Adicionar `font-display: swap` ao carregamento das fontes em `layout.tpl`
- Ou adicionar CSS de fallback de fontes no `style-critical.tpl`

**Solução C (se home hero):**
- Verificar se `style-home-v2.css` está bloqueando por cache busting agressivo
- Ajustar estratégia de carregamento

### OUT (o que NÃO será feito sem investigação prévia)
- Mover CSS em massa sem identificar as classes específicas que causam FOUC
- Remover o mecanismo `visible-when-content-ready` sem entender sua função
- Alterar `style-async.scss.tpl` sem analisar dependências de cascade

### Arquivos Potencialmente Impactados (confirmar após investigação)
| Arquivo | Mudança Potencial |
|---------|------------------|
| `static/css/style-critical.tpl` | Adicionar classes above-the-fold (max 10-15 por batch) |
| `layouts/layout.tpl` | Possível: `font-display: swap` nas fontes |
