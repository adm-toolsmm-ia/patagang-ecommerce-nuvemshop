## 🔍 INVESTIGAÇÃO: Onde Pode Estar o Cinza?

### Cenário 1: Cache do Navegador (MAIS PROVÁVEL)

**Problema:** v1.5.30 ainda não foi carregada pelo navegador
**Indicador:** Console mostra `📦 PATAGANG v1.5.28` ou `v1.5.29` ao invés de `v1.5.30`
**Solução:** Limpar cache (`Ctrl+Shift+Delete` → Tudo → Limpar) + recarregar (`Ctrl+F5`)

---

### Cenário 2: Classe CSS Auxiliar em Elemento Pai

**Problema:** Um elemento entre `<body>` e as seções tem classe como `.placeholder-container` ou `.background-color-var`

**Exemplo:**
```html
<!-- SE ISSO EXISTISSE (mas NÃO EXISTE) -->
<body>
  <div class="placeholder-container">  ← TEM rgba($main-foreground, 0.1) como background!
    <section class="patagang-section-top">
      <!-- Herda cinza do pai! -->
    </section>
  </div>
</body>
```

**Verificação:** Layout.tpl não tem divs/wrappers entre `<body>` e seções — CONFIRMADO ✅

---

### Cenário 3: CSS em style-async.scss.tpl Sobrescrevendo

**Problema:** CSS carregado assincronamente pode estar sobrescrevendo v1.5.30

**Investigação:** style-async.scss.tpl não tem nenhuma definição de `.section-advertising` (confirmar se há)

---

### Cenário 4: Elemento Específico DENTRO de .section-advertising

**Problema:** `.section-advertising * { background: ... }` em algum arquivo CSS

**Verificação Feita:** layout.tpl tem `section.patagang-section-top .section-advertising * { background-color: transparent !important; }` — Está protegido ✅

---

### Cenário 5: Nuvemshop Inserindo CSS Dinâmico

**Problema:** Nuvemshop pode estar injetando CSS ou HTML que sobrescreve

**Indicador:** F12 → Inspector → Elemento cinza → Styles mostra origem inesperada
