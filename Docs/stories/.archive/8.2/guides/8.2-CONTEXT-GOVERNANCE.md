## 🔗 LIVING DOCUMENTATION STRATEGY

### Princípio Core

**"Living Documentation" = Documentação que CRESCE com o projeto, nunca fica obsoleta**

Ao invés de:
```
❌ Criar doc no v1.0, depois ignorar quando v1.5 lança
❌ Documentação "congelada" que fica desatualizada
❌ Conhecimento tacit (só na cabeça do developer)
```

Fazer:
```
✅ Criar doc → Update doc → Versionar doc → Reference doc
✅ Cada histórico deixa "breadcrumb" para próxima
✅ Conhecimento explícito, rastreável, herdável
```

### Modelo de 4 Níveis

```
LEVEL 1: FUNDAÇÃO
├─ 8.2-PROJECT-HISTORY-CONTEXT.md
│  Responde: POR QUÊ?
│  Timeline: v1.0 → v1.5.41
│  Padrões IA identificados e categorizados
│
├─ LEVEL 2: INVENTÁRIO
├─ 8.2-PATTERNS-INVENTORY.md
│  Responde: QUAIS padrões mudar?
│  Checklist: 4 padrões legados → 4 refatorações
│  Referência: Central para Stories 8.3-8.5
│
├─ LEVEL 3: BLUEPRINT
├─ 8.2-FASE2-ARCHITECTURE-BLUEPRINT.md
│  Responde: COMO mudar?
│  Arquitetura: AS-IS (v1.5.41) → TO-BE (v1.6.0)
│  Execução: 6 fases de implementação
│
└─ LEVEL 4: GOVERNANCE (THIS DOC)
   8.2-CONTEXT-GOVERNANCE.md
   Responde: COMO herdar contexto?
   Herança: 8.2 → 8.3 → 8.4 → 8.5
   Manutenção: Living Documentation checklist
```

### Por que 4 Níveis?

| Level | Pergunta | Responde | Usado Por |
|-------|----------|----------|-----------|
| **1** | POR QUÊ? | Contexto histórico | @architect (review), Future devs (entender) |
| **2** | QUAIS? | Inventário padrões | @dev (v1.6.0), Stories 8.3-8.5 (referência) |
| **3** | COMO? | Implementação detalhada | @dev (v1.6.0 execução) |
| **4** | HERANÇA? | Context handoff | @sm, @architect (próximas histórias) |

**Lógica:**
- Sem LEVEL 1: Histórias futuras não entendem Por quê o código é assim
- Sem LEVEL 2: Não sabem quais padrões são os "bons" vs os "ruins"
- Sem LEVEL 3: Não conseguem implementar mudanças
- Sem LEVEL 4: Conhecimento fica siloed em uma pessoa

## 📖 COMO HISTÓRIAS FUTURAS HERDAM CONTEXTO

### Fluxo Padrão: Story N → N+1

```
Story 8.2 FASE 2 → Completa v1.6.0 (4 padrões refatorados)
                        ↓
        Documentação atualiza automaticamente:
        ├─ 8.2-PATTERNS-INVENTORY.md (padrões refatorados marcados ✅)
        ├─ 8.2-DOCUMENTATION-INDEX.md (novo version info)
        └─ NIVEL 1-4 documentação "CURRENT" para v1.6.0
                        ↓
@sm cria Story 8.3 (!important resolution)
        ├─ Lê 8.2-PROJECT-HISTORY-CONTEXT.md → entende contexto
        ├─ Lê 8.2-PATTERNS-INVENTORY.md → identifica padrões para 8.3
        ├─ Lê 8.2-FASE2-ARCHITECTURE-BLUEPRINT.md → vê "Hooks for 8.3"
        └─ Referencia como base: "Building on 8.2 LEVEL 2 patterns"
                        ↓
@dev implementa Story 8.3
        ├─ Segue 8.2 LEVEL 2 para entender "bons" padrões
        ├─ Cria NEW documento: 8.3-PATTERNS-INVENTORY.md (8.3 specific)
        └─ Referencia 8.2: "Consolidates on 8.2 refactorings"
                        ↓
Resultado: 8.3 contexto está CONECTADO a 8.2 (rastreável)
           Zero conhecimento perdido
           Cada história é "breadcrumb" para próxima
```

### Exemplo Concreto: Story 8.3 → 8.4

**Story 8.3: !important Resolution**

1. **@sm cria story:**
   - Lê 8.2-PROJECT-HISTORY-CONTEXT.md
   - Entende que CSS em 2 arquivos causou cascade issues
   - Story criada: "Consolidate CSS !important specificity"
   - AC referencia 8.2 LEVEL 2

2. **@dev implementa:**
   - Segue 8.2 PATTERNS-INVENTORY.md
   - Identifica que padrões humanos são "bons" (mantém)
   - Padrões IA refatorados são "consolidados" (8.2 já fez)
   - Cria: 8.3-PATTERNS-INVENTORY.md (novo, 8.3 specific)
   - Documenta: "Consolidates on 8.2 refactorings (v1.6.0)"

3. **Resultado v1.6.1 (Story 8.3 complete):**
   - CSS !important removido
   - Documentação: 8.3-PATTERNS-INVENTORY.md + update 8.2 refs
   - Próxima história (8.4) tem contexto: "8.3 fixed !important"

**Story 8.4: Template Cleanup**

1. **@sm cria story:**
   - Lê 8.3-PATTERNS-INVENTORY.md (resultado de 8.3)
   - Entende que CSS é consolidado
   - Agora pode focar em templates
   - Story criada: "Remove product-image-thumb.tpl orphan"
   - AC referencia 8.3 (e transitivamente 8.2)

2. **@dev implementa:**
   - Segue 8.2 + 8.3 PATTERNS-INVENTORY
   - Remove product-image-thumb.tpl
   - Consolida snipplets (nenhuma referência órfã)
   - Cria: 8.4-PATTERNS-INVENTORY.md
   - Documenta: "Builds on 8.2 v1.6.0 + 8.3 CSS cleanup"

3. **Resultado v1.6.2:**
   - Templates consolidados
   - Documentação: 8.4-PATTERNS-INVENTORY.md + references
   - Story 8.5 tem contexto: "Templates are clean, focus on JS"


## 🚨 FAILURE MODES & RECOVERY

### Scenario 1: Documentation Gets Out of Date

**Problem:** 8.2-PATTERNS-INVENTORY.md says "4 patterns refactored" but code shows pattern #2 still has lazyload duplo

**Prevention:**
- [ ] After each deploy, update PATTERNS-INVENTORY immediately
- [ ] Include "Version:" field with v1.6.0 date
- [ ] Run diff: "which patterns changed from last version?"

**Recovery:**
- [ ] Compare code vs documentation
- [ ] Update documentation to match code
- [ ] Add note: "Fixed staleness on 2026-03-24"

---

### Scenario 2: Story 8.3 Doesn't Know About 8.2 Patterns

**Problem:** @dev implementing Story 8.3 doesn't read 8.2-PROJECT-HISTORY-CONTEXT, reinvents wheel

**Prevention:**
- [ ] @sm creates 8.3 story with explicit reference: "See 8.2-PROJECT-HISTORY-CONTEXT for context"
- [ ] @po validates: AC references 8.2 (check 10-point checklist)

**Recovery:**
- [ ] @dev reads 8.2-PROJECT-HISTORY-CONTEXT mid-story
- [ ] Adjust implementation to use 8.2 patterns
- [ ] Document: "Consolidated with 8.2 patterns (refactoring #X)"

---

### Scenario 3: 4-Level Hierarchy Breaks (Missing LEVEL 2)

**Problem:** LEVEL 2 (PATTERNS-INVENTORY) deleted accidentally, next story has no reference

**Prevention:**
- [ ] `.claude/rules/file-structure-standards.md` protects docs/ from deletion
- [ ] git history preserves content if accidentally deleted
- [ ] DOCUMENTATION-INDEX.md references all LEVEL 1-4

**Recovery:**
- [ ] Check git history: `git log --oneline docs/guides/8.2-*`
- [ ] Restore: `git checkout HEAD~N -- docs/guides/8.2-PATTERNS-INVENTORY.md`
- [ ] Update date: "Restored from git history, re-validated 2026-03-24"
