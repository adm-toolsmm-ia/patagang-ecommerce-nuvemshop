### 3. User Story (Clear Intent)

```
As a screen reader user,
I want all form inputs to have associated labels,
So that I understand what information each input field requires.

ACCEPTANCE CONTEXT:
- Current State: Some form inputs missing labels (use placeholder only)
- Target State: All inputs have <label> with for attribute
- Coverage: Login, register, checkout, contact forms
- Standard: WCAG 3.3.2 (Labels or Instructions)
- Quality: Labels visible and meaningful (not placeholder)
```

### 4. Acceptance Criteria (Testable Checklist)

**AC-1: Label-Input Association**
```
□ All <input> elements have associated <label> element
□ Label uses for attribute matching input id
□ Example: <label for="email">Email</label> <input id="email">
□ Labels are NOT inside <span> or <div> wrapping input
□ All input types covered: text, email, password, number, select, textarea
□ Checkboxes and radio buttons: Labels clearly associated
```

**AC-2: Visible Labels**
```
□ All labels are visible to users (not hidden with display:none)
□ Labels positioned near inputs (above or left of input)
□ Label text is meaningful and describes field purpose
□ Labels are NOT just placeholder text
□ Example bad: <input placeholder="Name"> with no <label>
□ Example good: <label>Name</label> <input placeholder="Your full name">
```

**AC-3: Required Field Indicators**
```
□ Required fields: Label includes "*" or "(required)" text
□ Optional fields: Label includes "(optional)" if needed
□ Indicator position: Clear and visible
□ Color contrast: Red "*" visible on all backgrounds
□ Assistive text: Aria-label includes "required" for screen readers
□ Example: <label>Name <span aria-label="required">*</span></label>
```

**AC-4: Form Types Coverage**
```
□ Login form: All fields have labels (username, password, remember)
□ Register form: All fields labeled (name, email, password, confirm)
□ Checkout form: Shipping, billing, payment fields labeled
□ Contact form: All fields labeled (name, email, message, etc.)
□ Search form: Search input has associated label
□ Newsletter: Email input has label (not placeholder)
```

**AC-5: Screen Reader Compatibility**
```
□ NVDA (Windows): All labels announced with inputs
□ JAWS (Windows): Input purpose clear from label
□ VoiceOver (macOS): Labels associated and readable
□ iOS VoiceOver: Form inputs announce labels on focus
□ Android TalkBack: Labels associated with inputs
□ No duplicate announcements (label + aria-label)
```

**AC-6: WCAG 3.3.2 Compliance**
```
□ Axe DevTools audit: 0 violations for form labels
□ All inputs have associated labels
□ Labels are programmatically connected (for attribute)
□ No inputs labeled only by placeholder
□ Instructions visible for complex fields
□ Error messages associated with fields
```

**AC-7: Code Quality & Consistency**
```
□ HTML validation: No label-input association errors
□ CSS: Labels styled consistently
□ No console warnings about missing labels
□ Linting passes (npm run lint)
□ Code comments explain label-input relationships where complex
```

**AC-8: No Breaking Changes**
```
□ Existing form functionality unchanged
□ Form submission still works correctly
□ Visual styling of forms preserved
□ No JavaScript errors introduced
□ Mobile form usability unaffected
□ Accessibility enhancement only (no feature changes)
```
