### 3. User Story (Clear Intent)

```
As a developer,
I want duplicate template sections extracted to reusable partials,
So that template maintenance is easier and code duplication reduced.

ACCEPTANCE CONTEXT:
- Current State: Duplicate HTML blocks in multiple templates
- Target State: Shared partials in includes/ directory
- Examples: Product cards, component headers, footers
- Goal: Reduce template file count, improve maintainability
- Method: Identify duplicates, extract to partials, use includes
```

### 4. Acceptance Criteria (Testable Checklist)

**AC-1: Duplicate Identification**
```
□ Analyze templates: Identify duplicate blocks
□ Common patterns found: Product cards, headers, footers, sidebars
□ Example: Product card HTML appears in 5+ templates
□ Quantify: Count duplicated lines of code
□ Impact: Estimate maintenance benefit
□ Document: List of duplicates with locations
```

**AC-2: Partial Extraction**
```
□ Create includes/ directory (if not exists)
□ Extract product card: Create _product_card.html partial
□ Extract header: Create _header.html partial
□ Extract footer: Create _footer.html partial
□ Extract sidebar: Create _sidebar.html partial
□ Extract category section: Create _category_section.html partial
□ 5+ major partials created
□ Each partial: Parameterized for flexibility
```

**AC-3: Partial Integration**
```
□ Replace product cards: All instances use partial
□ Replace headers: All instances use partial
□ Replace footers: All instances use partial
□ Replace sidebars: All instances use partial
□ Replace category sections: Use partial
□ Test: All pages render identically after change
□ No missing includes: All places updated
```

**AC-4: Template File Reduction**
```
□ Before: Estimate 20-30 template files
□ After: Reduced via partial reuse
□ Code lines: Reduce duplicate lines by 30-40%
□ Maintainability: Single source of truth for each component
□ Flexibility: Partials parameterized for different use cases
□ Consistency: Identical rendering across all uses
```

**AC-5: Parametrization & Flexibility**
```
□ Product card partial: Parameters for title, price, image, link
□ Header partial: Parameters for nav items, logo, search
□ Footer partial: Parameters for links, copyright year
□ Sidebar partial: Parameters for content, width, classes
□ Category section: Parameters for title, items, layout
□ Examples: Documentation showing parameter usage
```

**AC-6: Testing & Validation**
```

□ All pages render: No template errors
□ All features work: Add to cart, navigation, search
□ Edge cases: Empty states, long text, mobile
```

**AC-7: Documentation & Maintenance**
