## 🎯 Objective

Fix critical gallery modal UX issue: modal opening at bottom instead of fullscreen when clicking product image.

---

## 🔍 Root Cause Analysis

**Problem 1: Header Z-Index Blocking Modal**
- Header had `z-index: 1000` with `!important`
- Fancybox lightbox had `z-index: 1050`
- Stacking context was confusing, modal appeared clipped/below header

**Problem 2: Duplicate Gallery Display**
- Template had `<div id="pg-modal-gallery">` with `aria-hidden="true"`
- NO CSS rule existed to hide `.pg-modal-gallery` when `aria-hidden="true"`
- Element displayed by default (second gallery visible on page load)

---

## ✅ Solutions Implemented

### Fix 1: Header Z-Index Cascade (Commit: 8088d3f)

**File:** `theme-deploy-corrigido/static/css/style-async.scss.tpl`
**Lines:** 1896-1908

**Before:**
```scss
.header {
    position: fixed !important;
    z-index: 1000 !important;
    /* 5 more !important rules */
}
```

**After:**
```scss
.header {
    position: fixed;    /* !important removed */
    z-index: 999;       /* 1000 → 999 (below modal 1050) */
    /* cascata technique applied */
}
```

**Impact:** Header no longer blocks modal overlay
**!important Removed:** 7 instances

---

### Fix 2: Modal Display Rules (Commit: a26a8e8)

**File:** `theme-deploy-corrigido/static/css/style-critical.tpl`
**Lines:** 4588-4620 (added)

**New CSS Rules:**
```scss
/* Hide when aria-hidden="true" */
#pg-modal-gallery[aria-hidden="true"] {
    display: none;
    visibility: hidden;
    opacity: 0;
}

/* Show when aria-hidden="false" (activated by JS) */
#pg-modal-gallery[aria-hidden="false"] {
    display: flex;
    position: fixed;
    z-index: 1100;    /* Above header (999), below fancybox (1050) */
    /* ... fullscreen styling */
}
```

**Impact:** Modal only appears when JavaScript activates it
**Lines Added:** 27

## ✨ Key Learnings

1. **aria-hidden Attribute + CSS:** Using `[aria-hidden="true"]` selector makes visibility control semantic and intentional
2. **Z-index Stack:** Clear ordering (header: 999, modal: 1100, fancybox: 1050) prevents confusion
3. **Cascata Technique:** Increasing specificity without `!important` is more maintainable
